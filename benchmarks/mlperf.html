MLPerf Training & Inference

The industry's real-workload AI benchmark — where NVIDIA, AMD, and Google actually compete head-to-head, not a synthetic FLOPS number — updated 2026-09-09.

1. What is MLPerf, and why does it matter?

MLPerf is run by MLCommons (founded 2020, evolved from the original MLPerf effort at Baidu/Google/Harvard/Stanford). It's fundamentally different from HPL/HPCG (§ elsewhere on this site): instead of a synthetic linear-algebra or memory-bandwidth workload, MLPerf measures actual model training-to-a-quality-target or actual model serving under realistic latency/throughput constraints. Two suites: MLPerf Training (wall-clock time to train to a specific quality target — not full convergence) and MLPerf Inference (throughput/latency under defined serving scenarios).

Why it matters

  • NVIDIA's real competitive battleground — AMD, Google, Intel, and every major system vendor publish results in the same rounds, on the same rules, unlike vendor marketing slides.
  • Real workloads, not synthetic FLOPS — HPL tells you peak compute; MLPerf tells you what a real LLM pretraining or serving job actually achieves on that hardware.
  • Strict, auditable rules — the Closed division locks the model/optimizer/hyperparameter space so results are a fair hardware+software-stack comparison, not different teams solving different problems.

What it's used for

  • Public competitive benchmarking (NVIDIA's MLPerf blog posts are a recurring marketing + engineering credibility event)
  • Procurement decisions — buyers use MLPerf results as a trusted, standardized comparison point
  • Internally: validating new hardware generations (GB300 vs GB200) and new software stacks before/alongside launch

3. Rules & divisions

Closed division

Model/optimizer/init/data-traversal mathematically fixed — only infrastructure and low-level implementation differ. This is the fair hardware-comparison number.

Open division

Freedom to modify model/approach — an innovation showcase, not a hardware comparison.

Availability tiers

Available (shipping today) / Preview (pre-release) / RDI (Research, Development, Internal) — tells you how real/purchasable the tested system is.

"Time to train to target quality" is precise and strict: the LLM pretraining benchmark trains only to a defined perplexity/loss threshold, not full convergence — specifically so the number reflects infrastructure speed, not training-recipe quality.

MLPerf Power uses the industry-standard SPEC PTDaemon interface (a third-party power analyzer, separate director machine, "dynamic ranging" for precision) — introduced in Inference v1.0 (2021), still the methodology today.

Source: MLCommons training rules, MLPerf Power docs, arXiv:2410.12032.

4. How results are measured

Every result is reported with: the benchmark task, division (Closed/Open), availability tier, system configuration (node/accelerator count and type, software stack versions), and the achieved metric — time-to-train (Training) or throughput/latency under the scenario's constraint (Inference). Because Closed-division rules fix everything except infrastructure, a faster time or higher throughput in Closed is a genuinely fair "this hardware+software stack is faster" claim — not an artifact of a better training recipe.

5. Real results — MLPerf Training v5.1 & Inference v6.0

Live-verified 2026-09-09. Every number below is sourced (MLCommons official release, NVIDIA/Lambda/Nebius blogs, HPCwire) — none simulated.

GB300 NVL72 vs GB200 NVL72 — same-generation-family speedup

NVIDIA won every benchmark in MLPerf Training v5.1. DeepSeek-V3 671B (new MoE benchmark) scaled to 8,192 GPUs on GB200 NVL72 — the largest-scale Blackwell submission in MLPerf Training to date. Prior round (v5.0): Blackwell delivered up to 2.6× higher performance vs previous gen. MLPerf Inference v6.0 added GPT-OSS 120B text generation, WAN-2.2 text-to-video, a VLM benchmark, updated DLRMv3, YOLOv11 — GB300 NVL72 led GPT-OSS 120B datacenter-closed tokens/sec, GB200 NVL72 close behind. Prior-round reference: H200 hit 33,000 tok/s on Llama 2 70B, 40% more than H100.

Sources: Lambda MLPerf Training v5.1, WCCFTech GB300 coverage, MLCommons April 2026 release, Nebius v6.0 results.

8. How to run / reproduce

Reference implementations are genuinely public and runnable by anyone — each benchmark directory in mlcommons/training or mlcommons/inference ships a Dockerfile, a dataset-download script, and a timed run script; an --accuracy flag validates the quality target is met. NVIDIA's own submission code is published in the results repos, so anyone can reproduce NVIDIA's numbers too, not just the reference baseline.

# General pattern (per-benchmark README has the exact commands)
git clone https://github.com/mlcommons/inference.git
cd inference/language/llama2-70b   # example: pick a benchmark directory
pip install mlc-scripts
mlcr run-mlperf,inference --model=llama2-70b --implementation=reference \
  --category=edge --division=open --device=cuda --quiet
Official submission requires MLCommons membership, adherence to the strict Closed/Open division rules, and a peer-review process before a result can be published in an official round — but just running the reference code for your own internal benchmarking needs neither membership nor review. For version-pinned reproduction, git checkout <version-tag> (e.g. v3.1) matches a specific past round.

Honest gap: no single universal "run this one command for any benchmark" exists — each benchmark's own README has its exact build/run steps. Source: mlcommons/inference README.
