AMD Instinct & ROCm

The other side of the GPU cluster market — MI300X to MI400, ROCm/RCCL/AMD-SMI/RVS tooling, AMD's Megatron fork, and the Instella open-model family — updated 2026-09-09.

1. What is AMD Instinct, and why does it matter?

AMD Instinct is AMD's datacenter GPU line — the primary alternative to NVIDIA's H100/H200/B200/GB200 for large-scale AI training and inference. This is the first non-NVIDIA vendor page on this site, added because a genuinely distinct, well-documented parallel stack exists: real hardware specs, a real software stack (ROCm), a real diagnostic/burn-in tool family, an official large-scale training framework fork, and a real from-scratch open-model family — not just "runs the same models as NVIDIA."

Why it matters

  • Real hyperscaler adoption — MI300X/MI325X deployed at scale by major clouds; the credible #2 in the AI accelerator market.
  • Genuinely competitive, not just cheaper — MI300X lands within 2-3% of H100 on real MLPerf Inference numbers (see §6); MI355X reaches near-parity with B200.
  • A real parallel ecosystem — ROCm mirrors CUDA's role, RCCL mirrors NCCL, AMD-SMI/RVS mirror nvidia-smi/DCGM — worth understanding even if you primarily work with NVIDIA hardware.

What's genuinely different (not a reskin)

  • Node interconnect topology — a true point-to-point mesh (Infinity Fabric), not a switched fabric like NVSwitch (§2).
  • RCCL is an honest, lagging fork of NCCL — AMD's own community describes it as such; new NCCL features take months to land in RCCL.
  • Instella — a real from-scratch open-model family trained entirely on MI300X, not just "we support Llama."

Node topology — a genuinely different architecture from NVSwitch

This is architecturally distinct from NVIDIA's approach: NVSwitch is a separate switch chip that all GPUs connect to (a star/switched topology); AMD's 8-GPU mesh is true point-to-point (7 peers = 7 direct links, no switch). Source: Hot Chips 2024 MI300X architecture deck.

3. Software stack

ROCm

AMD's CUDA-equivalent — the full compute stack (compiler, runtime, libraries: rocBLAS, hipBLAS, etc.). Mature, actively developed.

RCCL

The NCCL-equivalent collective comms library. By AMD's own community's characterization: "a fork of NCCL, basically a copy+paste carbon copy except it takes months for new NCCL features to reach RCCL." Real distinct bits: XCD/tile-aware channel placement, ring/tree construction reflecting the multi-hop Infinity Fabric topology (§2). Now hosted in the consolidated ROCm/rocm-systems monorepo (the standalone ROCm/rccl repo is retired/archived).

4. AMD's Megatron-equivalent training framework

AMD maintains an official ROCm fork of Megatron-LM, plus a newer Primus-Megatron integration. Supports Llama 3.3-70B, 3.1-8B/70B, DeepSeek, Mixtral. Ships ready-to-use Docker images (ROCm 6.4.1 + PyTorch 2.8.0a0).

Honest gap: no MFU/throughput benchmark numbers comparable to the 35-55% MFU range documented on the Megatron-LM page were found for AMD's training stack in this research pass. AMD's docs describe setup, not published efficiency numbers. Real MLPerf Training round-over-round gains are documented in §6 instead — those are sourced and real, just measuring something slightly different (submission-round speedup, not steady-state MFU).

5. Instella — AMD's from-scratch open model family

Instella-3B is trained entirely from scratch on MI300X — fully open (weights + data + training config + code), not just a fine-tune. AMD claims it outperforms other fully-open ~3B models and is competitive with Llama-3.2-3B, Gemma-2-2B, Qwen-2.5-3B (open-weight, not fully-open, comparison).

AGFHC — AMD GPU Field Health Check (Phase 3)

Minimum required suite = 14.67 hours:

  • all_lvl5 — 2hr sweep
  • hbm_lvl5 — 4×2hr with 5min thermal recovery between runs
  • gfx_lvl4 — 1hr
  • minihpl — 3hr compute-fabric integration test (AMD runs an HPL-equivalent as part of acceptance, same principle as NVIDIA — see the HPL page)
  • pcie_lvl2 — 10min
Pass = exit code 0 on every recipe. Failure message, quoted directly: "Do not proceed further. Report this issue to your system manufacturer immediately."

9. How to run it

Pull a ROCm container

docker pull rocm/pytorch:latest
docker run -it --network=host --device=/dev/kfd --device=/dev/dri \
  --group-add video --ipc=host --shm-size 16G rocm/pytorch:latest

Quick health check with RVS

./rvs -g              # list detected GPUs
./rvs -d 3             # verbose sanity run
./rvs -c conf/gst_single.conf   # GPU Stress Test module

Check GPU status

amd-smi monitor --power-usage --temperature --gfx --mem
